# Student Record Processing System

## Introduction

This project is a C++ systems programming application for processing student records. It stores each student's first name, surname, homework results, exam result, and calculated final grade. The application will be developed incrementally, starting with the `Person` class and later adding dynamic homework input, average and median calculations, random score generation, file processing, sorting, and formatted output.

The project uses the Rule of Three (`destructor`, `copy constructor`, and `copy-assignment operator`) as required by the assignment. Homework results will be represented using `std::vector` so that the program can support a variable number of homework assignments.

## Basic final-grade formula

The initial calculation uses the weighted formula:

```text
Final grade = 0.3 × homework result + 0.7 × exam result
```

Where `homework result` can later be calculated either as the arithmetic average or as the median of the homework scores. The program will display both calculation methods in the later stages of development.

## Data format

The supplied student data uses the following general structure:

```text
Name Surname ND1 ND2 ... NDn Egz.
```

The number of homework results is not fixed. The final implementation will read the homework values into a `std::vector` and treat the last numeric value as the exam result.

## Current version

The current branch is the `v1.0` development branch based on the stable
`v0.25` release. The `v0.25` processing implementation uses
`std::deque<Person>`, and the common benchmark also runs equivalent
`std::vector<Person>` and `std::list<Person>` implementations. The new
`strategy_benchmark.cpp` compares the two `v1.0` categorization strategies for
all three containers.

Homework input ends with `-1`, followed by the exam score. For example:

```text
Anna Smith 8 9 10 -1 9
```

After entering the record, choose `1` for the average or `2` for the median. For an even number of homework scores, the median is the average of the two middle sorted scores.

The program also supports random data generation. Choose `2`, then enter the first name, surname, and number of homework assignments. Homework and exam scores are generated as integers from `0` to `10`.

Choose `3` to open `Students.txt`, skip its header, read all valid student records, store them in the active container, and sort them by surname. On the current `v0.25` stage, the active container is `std::deque<Person>` and the program displays both final-grade calculations for every loaded student.

The project was tested with manual input, random input, file input, average calculation, median calculation, and an even number of homework scores. Temporary executable files are not kept in the repository.

The `v0.2` branch uses `StudentException` to report missing or empty files, invalid file headers, malformed student records, out-of-range scores, and invalid menu or calculation choices. Errors are caught in `main.cpp` and reported without an unhandled exception.

Large test files are generated by the separate `generator_main.cpp` utility. The utility creates `Students_1000.txt`, `Students_10000.txt`, `Students_100000.txt`, `Students_1000000.txt`, and `Students_10000000.txt` in `generated_data/`. These generated files are ignored by Git because the largest file is intentionally not part of the source repository.

The project also includes a preliminary `Students.txt` file with sample student records.

## Build from the beginning

### Unix Makefile

From the project root, run:

```bash
make
```

This builds `students`, `processor`, `generate_students`,
`container_benchmark`, and `strategy_benchmark`. To remove build outputs, run:

```bash
make clean
```

### CMake

CMake can be used on Unix, Windows, or another supported platform:

```bash
cmake -S . -B build
cmake --build build --config Release
```

The executables are placed in `build/` on Unix and in a configuration
subdirectory on multi-configuration generators such as Visual Studio.

### Direct compilation

The equivalent direct command for the interactive application is:

```bash
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp Person.cpp StudentManager.cpp -o students
./students
```

To build and run the large-file generator:

```bash
g++ -std=c++17 -Wall -Wextra -pedantic \
    generator_main.cpp StudentFileGenerator.cpp -o generate_students
./generate_students generated_data
```

To process one generated file, read all records into `std::deque<Person>`, and
write the two categories, build and run the processor:

```bash
g++ -std=c++17 -Wall -Wextra -pedantic \
    processor_main.cpp Person.cpp StudentManager.cpp -o processor
./processor generated_data/Students_10000.txt \
    generated_data/Students_10000_passed.txt \
    generated_data/Students_10000_failed.txt
```

To compare all three containers on one input file, build and run the common
benchmark:

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic \
    container_benchmark.cpp Person.cpp -o container_benchmark
./container_benchmark generated_data/Students_10000.txt benchmark_output
```

The benchmark reports CSV timings for `vector`, `list`, and `deque`. The
results for all five required file sizes are recorded in
[`container_comparison_results.md`](container_comparison_results.md).

The split rule is:

```text
final grade >= 5.0  -> passed
final grade < 5.0   -> failed
```

Both output files keep the same student-record format as the input file, so
they can be read again by the application. Each output category is sorted by
surname and then by first name. The processor reports separate timings for
reading, sorting, splitting, writing, and the complete operation in
milliseconds using `std::chrono::steady_clock`.

The benchmark results for all five required file sizes are recorded in
[`performance_results.md`](performance_results.md).

## v1.0 requirements review

Release `v1.0` will optimize the `v0.25` implementation while preserving the
same student-record format and the three-container comparison. The work will
compare two categorization strategies for `std::vector<Person>`,
`std::list<Person>`, and `std::deque<Person>`:

1. **Strategy 1:** keep the original students container unchanged and copy
   students into new `passed` and `failed` containers of the same type.
2. **Strategy 2:** move failed students into one new `failed` container and
   remove them from the original container, leaving only passed students in
   the original container.

Both strategies will be measured for reading, sorting, categorization,
deletion or copying where applicable, writing, and total execution time on the
five existing data sizes. The results will be checked for record conservation
and identical pass/fail classification.

After the initial comparison, the fastest container and strategy will be
refactored with suitable algorithms from `<algorithm>`, including candidates
such as `std::copy`, `std::remove_if`, `std::partition`, and
`std::stable_partition`. The before-and-after results will be documented.

The final release must also provide a Unix `Makefile`, a portable
`CMakeLists.txt`, a usage guide starting with the build step, a clean source
repository, synchronized `v1.0` and `master` branches, and Release `v1.0`.

## v1.0 strategy benchmark

The `strategy_benchmark.cpp` program implements both required categorization
strategies for all three containers. Strategy 1 keeps the original container
and copies every student into a new `passed` or `failed` container. Strategy 2
creates only a `failed` container, moves failed records to it, erases them from
the original container, and leaves passed records in the original container.

The program validates that no records are lost and reports the number of
original, passed, and failed records. It measures reading, sorting, splitting,
writing, and total execution time in milliseconds. The menu can run one
strategy or both strategies and one container or all containers.

Build it with:

```bash
g++ -std=c++17 -O2 -Wall -Wextra -pedantic \
    strategy_benchmark.cpp Person.cpp -o strategy_benchmark
```

Run both strategies on all containers using the menu:

```bash
./strategy_benchmark
```

The non-interactive form is useful for repeatable tests:

```bash
./strategy_benchmark generated_data/Students_10000.txt \
    strategy_output 3 4
```

Here, `3` selects both strategies and `4` selects all containers. The output
files contain the selected strategy, container, and category in their names,
for example `vector_strategy1_passed.txt` and
`deque_strategy2_failed.txt`.

The categorization implementation uses algorithms from `<algorithm>`:

- `std::copy_if` copies passed and failed records for Strategy 1 while the
  original container remains unchanged.
- `std::stable_partition` places passed records before failed records for
  Strategy 2 while preserving the relative order inside each group.
- `std::make_move_iterator` moves the failed range into its new container,
  after which the failed range is erased from the original container.

These algorithms replace the manual categorization loops while preserving the
required record counts and output ordering.

The before-and-after measurements are documented in
[`algorithm_comparison_results.md`](algorithm_comparison_results.md). The
comparison completed for both versions through 1,000,000 records. The
algorithm version also completed all six 10,000,000-record cases; the baseline
10,000,000-record run exceeded the available two-hour measurement window, so
the report leaves those baseline values unspecified rather than estimating
them.
